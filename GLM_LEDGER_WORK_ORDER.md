## 3. THE CORE PROBLEM: a private copy of the design system

Ledger *looks* close because it reimplements the design system locally rather than consuming it. That means it matches today by coincidence and will drift tomorrow — it inherits none of the fixes we just made to the shared primitives. This is the main thing to fix.

**a) Two hand-rolled dropdown menus.** `LedgerPage.jsx` has **no `Menu` import at all**. Instead it defines a private `POPOVER_CLASS` (`:19`) plus `MENU_ITEM` / `MENU_ITEM_DANGER` (`:29-30`) and positions menus by hand:
- `:332` — settings menu, `absolute right-0 top-full mt-2 w-48 z-50`
- `:559` — row context menu, `fixed z-100 w-48`

Verified live: the rendered popup has `role: none`, contains no `role="menuitem"`, has no arrow-key navigation and no managed focus. `z-100` **is not on the named scale at all** (the scale tops out at `z-toast` 80), and `z-50` puts a menu on the same layer as dialogs. Migrate both onto `composed/Menu`, which gives anchoring, width, collision, roles, keyboard nav and the correct `z-popover` layer for free.

**b) Modals use raw form elements.** `LedgerModals.jsx` uses bare `<input>` (`:50`, `:117`), `<textarea>` (`:104`, `:169`), and `<button>` (`:64`, `:84`, `:127`, `:128`, `:182`, `:199`, `:200`) styled by private `INPUT_CLEAN` / `LABEL_CLASS` constants from `decisionStyles.js` — instead of `Input`, `Textarea`, `Field`, `Button`, `EntityForm`. Consequence: none of these controls have the `h-11` / `rounded-3xl` family, the focus-visible ring behaviour, or `Field`'s label/error handling. The three dialogs should be built from `EntityForm` + `Field` the way Chronos's task/signal/session forms are — go read `src/features/Chronos/ChronosModal.jsx` for the pattern.

**c) Hand-rolled buttons.** Five `h-8 px-3 rounded-lg` buttons (`LedgerPage.jsx:306, 315, 325, 443, 462`) instead of the `Button` primitive. One also carries an arbitrary `shadow-[0_0_15px_var(--overlay)]` rather than a shadow token.

**d) Not consuming `SectionLabel` / `CountPill` / `IconButton`.** The "OPEN 3" / "REVIEWED 3" group headers hand-roll what `SectionLabel` + `CountPill` already do, and `DecisionCard` exports its own `SectionDivider`.

**e) Mixed radius family.** Tallied across Ledger: `rounded-full` ×17, `rounded-lg` ×16, `rounded-md` ×3, `rounded-xl` ×2, `rounded-2xl` ×1. Settle on tiers and apply them: pills/dots `rounded-full`, chips `rounded-lg`, cards/tiles `rounded-xl`, panels/containers `rounded-2xl`/`rounded-3xl`. (Chronos uses exactly this split — match it rather than inventing a new one.)

## 4. CONCRETE BUGS — all verified live at 1024×768

1. **The Outcome Scorecard card overflows.** Two elements extend **21px past the viewport** — `flex items-center gap-1.5 text-xs tracking-wider uppercase` and `text-subtle-foreground tabular-nums`. Visible symptoms: the header "OUTCOME SCORECARD" wraps onto two lines and collides with its "REVIEWED ONLY" caption (which is passed into `SectionCard`'s `action` slot and is too long for it); the radar chart's axis labels are clipped to "ure" and "Mix"; and the "33% MIXED 33% FAIL…" legend is cut off at the card's right edge. Fix the card's internal layout — and consider whether that caption belongs in the `action` slot at all.

2. **No dock clearance.** Measured: `main` bottom is 768px while the floating dock's top is 690px, so the last row of decision cards sits **78px underneath the dock**. Opus solves this with `style={{ paddingBottom: 'calc(var(--dock-h) + 2rem)' }}` (`OpusLayout.jsx:28`) — apply the same. Check it at both the mobile tab-bar and desktop floating-dock breakpoints.

3. **Decision cards are not keyboard reachable.** `DecisionCard.jsx:25` is a `<div>` with an `onClick` and no `role`, no `tabIndex`, no `onKeyDown`. A keyboard user cannot open a decision. (Chronos's rows have the same gap — if you fix the pattern, note it so it can be applied there too, but don't go edit Chronos in this pass.)

4. **The settings gear button has no accessible name.** It reads as an unlabeled `button` in the accessibility tree. Every icon-only control needs a label — `composed/IconButton` enforces this via a required `label` prop.

5. **Meta chips wrap inconsistently between cards.** With realistic data, one card fits `MEDIUM / REVERSIBLE / 60% CONF` on one row while its neighbour wraps `60% CONF` to a second row, so sibling cards in the same grid row have different internal rhythm and ragged heights. Decide a deterministic layout (fixed chip row, truncation, or a consistent two-row block).

6. **The assumption-list fade mask clips mid-word.** The overflow gradient cuts "Assumption B" mid-text, which reads as broken rather than truncated. Either clamp to whole lines or add an explicit "+N more".
